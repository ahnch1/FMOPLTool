# AdLib Visual Composer 재현 (C#) — 필요 기능 정리

목표: BNK 악기를 채널(보이스)마다 할당 → 건반(피아노롤) 악보에 노트 배치 → OPL2 에뮬레이션으로 재생

---

## 0. 원본 화면에서 확인된 내용 (스크린샷 기준)

Visual Composer 편집 화면(640×400 흑백 DOS 그래픽, 곡 이름 `boogie`)에서 확인한 것.

**메뉴/조작**
- 상단 메뉴: `F5 File` · `F6 Edit` · `F7 Playback` · `F8 Display` · `F9 Options` · `F10 Help` (펑션키로 호출)
- 화면 우상단에 현재 곡 이름 표시
- 마우스 포인터로 조작하는 GUI (스크롤바, 라디오 버튼)

**보이스 선택 (라디오 버튼)**
- `1 2 3 4 5 6 BD SD TO CY HH All`
- 멜로딕 6 + 퍼커션 5(베이스드럼, 스네어, 탐탐, 심벌, 하이햇) = **리듬 모드(11보이스) 화면**
- `All`: 모든 보이스를 한 화면에 표시
- 멜로딕 모드(9보이스)일 때 `1~9`로 바뀌는지는 미확인

**악보(피아노롤) 영역**
- 좌측에 세로 피아노 건반, 오른쪽에 격자
- 세로 = 음높이, 가로 = 시간. 노트는 **가로 막대**(막대 길이 = 음 길이)
- 격자선: 점선(박/세분), 실선(마디 구분으로 보임)
- 선택한 보이스의 노트는 굵은 막대, **다른 보이스의 노트는 얇은 점선 형태로 함께 표시**되는 것으로 보임
- 상하 스크롤바와 좌우 스크롤바, 좌하단에 `1:1` (줌/스케일 표시로 보임)
- 좌상단에 도구 아이콘 2개(연필, I형 커서). 각각 입력/선택 도구로 추정되나 정확한 기능은 미확인
- 건반 위 `Instr.` 행: 현재 위치(커서)의 **악기 이름**(예: `elguit2`)을 표시. 악기 교체가 악보 위쪽 전용 행에서 이루어지는 것으로 보임
- 우상단 `B` 상자: 용도 미확인 (현재 음 이름 또는 모드 표시일 가능성)

**원본에 보이지 않는 것** (필요하면 현대식 확장으로 추가)
- 채널 목록 패널(뮤트/솔로/볼륨 슬라이더), 마디 번호 표시, 재생 커서가 이 화면에는 없음. 재생 중 화면은 미확인

## 0-1. 우선순위 요약

| 단계 | 범위 |
|---|---|
| **MVP** | BNK 로드, 채널별 악기 할당, 피아노롤 편집, OPL2 재생 |
| **v1** | 템포/볼륨 트랙, ROL 저장·불러오기, 리듬 모드, 루프 재생 |
| **v2** | 악기 편집기, WAV/VGM 내보내기, MIDI 가져오기, 가사 |

## 1. 악기 뱅크 (BNK)

- [ ] `.BNK` 파일 열기 (헤더 `ADLIB-` 시그니처, 버전, 이름 목록, 악기 데이터 파싱)
- [ ] 악기 이름 목록 표시 + 검색/필터
- [ ] 악기 1개 = 오퍼레이터 2개(모듈레이터/캐리어) 파라미터 + 웨이브셀렉트 2개 + 피드백/커넥션
  - 오퍼레이터 파라미터: KSL, 멀티플, 피드백, 어택, 서스테인레벨, EG타입, 디케이, 릴리즈, 토탈레벨, AM, 비브라토, KSR
- [ ] 퍼커션 악기 구분 (percussion 플래그, 보이스 번호 8~10 등)
- [ ] 여러 BNK 동시 로드 (표준 `STANDARD.BNK`, `DRUM.BNK` 등)
- [ ] 악기 미리듣기 (목록에서 선택 → 건반 클릭으로 시음)
- [ ] (v2) `.INS` 단일 악기 파일 가져오기

## 2. 채널(보이스) 관리

- [ ] 보이스 선택 라디오 버튼: `1~6, BD, SD, TO, CY, HH, All` (원본 방식)
- [ ] (확장) 채널 목록 패널: 이름, 악기, 볼륨, 뮤트, 솔로, 색상 — 원본 화면에는 없음
- [ ] 채널별 BNK 악기 할당 (드롭다운 또는 드래그)
- [ ] 곡 중간 악기 교체 이벤트 (Instrument 트랙)
- [ ] 채널 수 모드
  - 멜로딕 모드: 최대 9채널
  - 리듬 모드: 멜로딕 6 + 퍼커션 5 (BD, SD, TOM, CYM, HH) = 11채널
- [ ] 채널 추가/삭제/순서 변경
- [ ] 채널별 볼륨, 피치 벤드 트랙

## 3. 건반 악보 (피아노롤) 에디터

- [ ] 좌측 건반(세로) + 시간축(가로) 그리드
- [ ] 노트 추가(클릭/드래그), 삭제, 이동, 길이 조절
- [ ] 다중 선택, 복사/붙여넣기, 잘라내기
- [ ] 퀀타이즈(스냅): 1/1, 1/2, 1/4, 1/8, 1/16, 3연음 등
- [ ] 줌(가로/세로), 스크롤, 마디/박 눈금선
- [ ] 현재 채널 강조, 다른 채널은 흐리게 표시 (고스트 노트)
- [ ] 단성 제약: OPL 한 보이스당 동시 1음 → 겹치는 노트 자동 방지/경고
- [ ] 노트 클릭 시 시음 (입력 피드백)
- [ ] Undo / Redo
- [ ] 컴퓨터 키보드/MIDI 키보드로 입력 (v2)

## 4. 보조 트랙 (Visual Composer 특유 기능)

- [ ] **템포 트랙**: 박자 변화(BPM), 마디 단위 편집
- [ ] **볼륨 트랙**: 채널별 시간대별 볼륨 (0.0~1.0)
- [ ] **악기 트랙**: 시점별 악기 변경 마커 (원본은 건반 위 `Instr.` 행에 악기 이름 표시)
- [ ] **피치 트랙**: 피치 벤드 (v1)
- [ ] 박자표(예: 4/4) 및 Ticks per beat 설정
- [ ] (v2) 가사 트랙(Text)

## 5. 재생 엔진

- [ ] **OPL2(YM3812) 에뮬레이터** 연동 — Nuked-OPL3 / DOSBox DBOPL의 C# 포팅 또는 P/Invoke
- [ ] 오디오 출력: NAudio(WASAPI) 또는 CSCore, 샘플레이트 49716Hz 계열 → 44.1/48kHz 리샘플
- [ ] 이벤트 시퀀서: 틱 단위 스케줄링 (노트온/오프, 악기 변경, 볼륨, 템포)
- [ ] F-Number / Block 계산 테이블 (MIDI 노트 → OPL 주파수)
- [ ] 재생 / 일시정지 / 정지 / 처음으로
- [ ] 재생 위치 커서 표시 + 자동 스크롤
- [ ] 구간 반복(루프), 클릭한 위치부터 재생
- [ ] 템포 배속
- [ ] 채널 뮤트/솔로 실시간 반영
- [ ] 오디오 스레드와 UI 스레드 분리 (언더런 방지)

## 6. 파일 입출력

- [ ] 프로젝트 저장/불러오기 (자체 JSON 포맷 — 개발 편의)
- [ ] `.ROL` (Visual Composer 원본 포맷) 불러오기/저장
- [ ] `.BNK` 읽기 (필수), 쓰기 (v2, 악기 편집기용)
- [ ] (v2) WAV 렌더링 내보내기
- [ ] (v2) VGM / IMF / DRO 내보내기 (OPL 레지스터 로그)
- [ ] (v2) 표준 MIDI(`.mid`) 가져오기/내보내기

## 7. UI 구성 (WPF 또는 WinForms/Avalonia)

- [ ] 메인 창: 상단 툴바(재생 컨트롤, 템포, 스냅) / 좌측 채널 패널 / 중앙 피아노롤 / 하단 보조 트랙
- [ ] 악기 브라우저 패널 (BNK 목록)
- [ ] 상태바: 현재 마디:박:틱, 선택 노트 정보
- [ ] 단축키 (스페이스=재생/정지, Del, Ctrl+Z/Y/C/V 등)
- [ ] 다크/라이트 테마 (선택)

## 8. (v2) 악기 편집기

- [ ] 오퍼레이터 파라미터 슬라이더/숫자 입력
- [ ] 실시간 시음
- [ ] 엔벨로프 그래프 시각화
- [ ] 새 BNK 저장

## 9. 기술 스택 제안

| 영역 | 후보 |
|---|---|
| 언어/런타임 | C# / .NET 8 |

## 10. 구조 (프로젝트 분리 제안)

```
AdlibComposer.Core      // 모델: Song, Channel, Note, Instrument, 이벤트
AdlibComposer.Formats   // BnkReader, RolReader/Writer, JSON
AdlibComposer.Audio     // OplEmulator, Sequencer, AudioOutput
AdlibComposer.App       // UI (피아노롤, 채널 패널 등)
```

## 11. 확인 필요 사항

- ROL/BNK 정확한 바이너리 스펙 (원본 카드 부속 문서 또는 분석 자료 기준)
- 리듬 모드를 MVP에 넣을지 여부
- 목표 호환 수준: 원본 ROL 100% 호환 vs 자체 포맷 우선
